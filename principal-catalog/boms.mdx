# BOMs

A bill of materials (BOM) defines how a SKU is produced: the components it consumes, the outputs it yields, and what each output is to the bill: its main product, a co-product or a by-product. Manage BOMs at `/principal/boms` in the **Principal Catalog** section.

<Note>
Your organization may use a different name for BOMs. Administrators can rename catalog terms in **Settings** → **Terminology**. See [Terminology](/administration/terminology).
</Note>

## BOM list

The list groups BOMs under the SKU each one makes: its main output, and also each co-product. A SKU with several BOMs, for example one per co-packer, shows them together, oldest first. Each group header shows the SKU's code, its name and how many BOMs it has. Click **Open SKU** in the header to go to the SKU's **BOM** tab.

Each row shows the BOM's name and its **Status**:

| Status | Meaning |
|--------|---------|
| **Draft** | Still being written |
| **Active** | Planned wherever a production rule switches it on (see [Which BOMs run where](#which-boms-run-where)) |
| **Archived** | Kept as history |

Status is only where the BOM is in its life. Production rules decide whether the plan runs it. A BOM with co-products is listed under each of them as well as under its main output. If it has by-products, the row says **Also makes** and names them.

- **Search** by BOM name, notes, or the code or name of a SKU the BOM produces.
- **Filter** by **Status** (everything but **Archived** by default), **Used as** (End product or Component), **Type** (the SKU type of what the BOM produces) and **Size** (component count ranges).
- Click the arrow at the start of a row to open the BOM's components underneath it. There you can add and remove components and change each one's quantity, unit and optional flag without leaving the list. Each change saves as you make it.
- Click a row to open the BOM's page.
- Click **New BOM** to create one.

Each row's menu offers **Open**, **Edit metadata**, and **Delete**. Deletion asks for confirmation and can fail if a policy still references the BOM.

### Columns and export

Open **Table Settings** to show or hide columns and to export. These columns are hidden until you turn them on:

- **Used as**: **End product** when no other BOM uses what this BOM makes, or **Component of N BOMs**.
- **Components**: how many components the BOM has.
- **Notes**.

**Export CSV** downloads the BOMs the current search and filters show. Each row has the SKU, BOM, status, used as, component count, also-makes, SKU type and notes, whether or not those columns are showing.

## Creating a BOM

<Steps>
  <Step title="Open the dialog">
    Click **New BOM** on the list page.
  </Step>
  <Step title="Name it and pick the output">
    Enter a **Name** and optional **Notes**, then choose the **Produces SKU** — the main SKU this BOM produces. Co-products and by-products can be added later from the detail page.
  </Step>
  <Step title="Add line items">
    Click **Add line item** for each component. Pick the component SKU with the searchable picker, then set its quantity, unit, and optional notes.
  </Step>
  <Step title="Create">
    Click **Create BOM**.
  </Step>
</Steps>

When editing an existing BOM from the dialog, only the name and notes are editable — line items are managed on the detail page.

<Tip>
You can also build a BOM from a SKU's detail page: on its **BOM** tab, adding the first component creates a BOM automatically with that SKU as the main output. See [SKUs](/principal-catalog/skus).
</Tip>

## BOM detail page

The header shows the BOM's status and an **Export CSV** action for its line items. The page has two tabs: **Overview** and **Inputs & outputs**. You can link to the second tab directly by adding `?tab=inputs` to the page address.

### Overview

- **Metadata:** edit the BOM's **Name** and **Notes**. A badge says **End product** when no other BOM uses what this BOM makes. Otherwise it says **Sub-assembly · N**, where N is the number of other BOMs that use it as a component. A yield rate line appears when a yield-rate policy targets an output SKU.
- **Other BOMs of** the SKU: every other BOM that makes the same SKU, each with its status. Click one to open it.
- **Used in:** every BOM that takes something this BOM makes as a component, with what that BOM produces and its status.

### Inputs & outputs

The **Inputs & outputs** tab holds the BOM's **Outputs** and **Line items**.

#### Outputs

The **Outputs** section lists what the BOM produces: each row has the SKU, a **Yield qty**, a **Kind**, and a remove button. Click **Add output** to add one via the component picker; a new output starts as a co-product. Output changes save immediately.

Each output has one of three kinds:

| Kind | What it means |
|------|---------------|
| **Main** | The product the BOM is for. Every BOM has exactly one. |
| **Co-product** | An equal product of the same run — for example a premix run that makes two premixes alike. The BOM belongs to it as much as to the main. |
| **By-product** | Something the run makes along the way, such as a seconds can. The BOM shows it only as **Also makes**. |

Choosing **Main** for another output makes it the main, and the previous main becomes a co-product. The main output can't be changed to another kind or removed while other outputs exist: make another output main first. Outputs created before kinds existed are main (the one that was primary) or co-products (the rest). On the BOM list, a BOM is listed under its main output and under each co-product, and its row names its by-products under **Also makes**.

#### Line items

The **Line items** section lists components with position, quantity, unit, and an optional flag. Click **Add component** to add one, drag rows to reorder, and edit quantities and units inline. Removing a component marks it for removal (struck through, with **Restore**) until you commit. Line item edits are staged: a sticky bar tracks unsaved changes with **Discard** and **Save all**.

### Component picker

The picker used for outputs, line items, and the SKU detail BOM tab is a searchable dialog: type a code, name, or description, and results appear grouped by each SKU's primary group. Click a SKU to select it. SKUs already used in the BOM (and the BOM's own outputs) are excluded, and circular references — a component that directly or indirectly consumes a SKU this BOM produces — are blocked.

## Which BOMs run where

A SKU can have several BOMs, for example one per co-packer. Whether a BOM runs at a site is set only by **production rules** (`assign_production` policies), never by the BOM's status. A production rule switches BOMs on at one of three levels:

| Level | The rule | Example |
|-------|----------|---------|
| One BOM at one site | Names the SKU, the site (or a line there), and the BOM | "FG0373 · True Spice · TS BOM → yes" turns on only the TS BOM at True Spice |
| One BOM everywhere | Names the SKU and the BOM, and no site | "FG0373 · IB BOM → yes" turns on the IB BOM at every production site |
| The whole SKU at a site | Names the SKU and the site, and no BOM | "FG0373 · Mamata → yes" turns on every BOM of FG0373 at Mamata |

**No rule means off.** A BOM no enabled production rule covers is not planned at that site. There are no "no" rules: switching something off disables the rule that switches it on.

### Switching a BOM or SKU on or off

You can switch one BOM, or the whole SKU, on or off at one site or everywhere. A switch only adds or disables production rules. Rankings, and rates or capacities that name the BOM, stay as they are.

| You switch | What changes |
|------------|--------------|
| A BOM **on** at a site | A rule naming the BOM at that site is added, unless one already covers it |
| A BOM **on** everywhere | A rule naming the BOM with no site is added |
| A BOM **off** where its own rule covers it | That rule is disabled |
| A BOM **off** where a whole-SKU rule covers it | The whole-SKU rule is **split**: it is disabled and replaced by one rule per remaining Active BOM, so the other BOMs keep running |
| The whole SKU **on** at a site | A rule naming the SKU and the site, and no BOM, is added |
| The whole SKU **on** everywhere | A rule per Active BOM, with no site, is added |
| The whole SKU **off** | Every rule switching it on there is disabled |

After a split, a BOM you add to the SKU later is not on at that site until you switch it on there. If a rule you disable also covered other sites, those sites each get their own rule, so they keep running what they ran.

**Every switch shows a preview first.** It lists the rules it will add, disable, or split, and for each site the BOM it runs now and the BOM it will run afterwards, or that the site will stop making the SKU. Nothing changes until you confirm. If the rules change between the preview and your confirmation, you're asked to preview again.

For example, Mamata makes FG0373 under "FG0373 · Mamata → yes" and ranks TS first, then IB. Switching IB off at Mamata previews: "Mamata: still runs TS. IB off here. IB still on at IB Foods." Confirming replaces the Mamata rule with "FG0373 · Mamata · TS → yes" and "FG0373 · Mamata · Evo → yes".

A switch is refused, and nothing changes, when:

- The rule to change covers other SKUs too, such as a rule on a SKU group. Changing it would change every SKU in the group, so the preview names the rule instead.
- The rule to change holds other rules in the same policy, which disabling it would turn off too.
- You switch on an **Archived** BOM. You can switch on a **Draft** BOM, but it isn't planned until you make it Active.

Where several BOMs are on at one site, the site's BOM ranking picks which one new runs use. With no ranking, the oldest BOM is used and the plan flags the site so you can rank them. Rules about a BOM, such as a throughput rate for it on a line, apply whenever that BOM runs.

### BOM status

A BOM's status is where it is in its life. It never switches a BOM on or off.

| Status | Meaning |
|--------|---------|
| **Draft** | Still being written. It can carry production rules, but it is never planned until you make it **Active**. |
| **Active** | Planned wherever an enabled production rule covers it. |
| **Archived** | Kept as history; its components and outputs can't change. Archiving disables every production rule that names the BOM and removes it from every site's ranking. Making it Active again does not turn those rules back on: enable the ones you want. |

### New revisions from a connected system

When your BOMs come from a connected system such as NetSuite, a formula change there is a new revision of the BOM, for example **FG0373-BOM1-REV2** after **FG0373-BOM1-REV1**. Each sync keeps every revision's components in step with the source and changes nothing else.

- **A new revision arrives as a Draft BOM** on the SKU it makes, named for the revision. It has no production rules and no place in any site's ranking, so it runs nowhere.
- **The previous revision is untouched.** It keeps its status and its rules, and keeps running wherever it ran.
- **To start using the new revision**, make it **Active** and add a production rule for it at each site it should run (and rank it there if the site runs several BOMs). Disable the previous revision's rules where it should stop.
- **A revision the source marks inactive keeps its status and its rules here.** The sync reports it as inactive in the source and never switches a BOM on or off. Disable its production rules if it should stop running.

## Best practices

<AccordionGroup>
  <Accordion title="Pick the main and the kinds deliberately">
    The main output is what the BOM is "for", and production defaults follow it. Mark a second output as a co-product only when the run is as much for it as for the main; anything incidental is a by-product.
  </Accordion>
  <Accordion title="Use sub-assemblies for shared intermediates">
    If several finished goods share a built component, give that component its own BOM. The list's **Used as** column and filter show which BOMs are end products and which are components of other BOMs.
  </Accordion>
  <Accordion title="Match line item units to the component's conversions">
    A line item's unit must be one the component SKU actually defines. Set up unit conversions on the component SKU first so quantities mean what you intend.
  </Accordion>
  <Accordion title="Check Used in before deleting">
    A BOM that other BOMs use, or that a policy names, is load-bearing. Check the **Used in** panel on its **Overview** tab before you delete it.
  </Accordion>
</AccordionGroup>

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| Adding a component is blocked as circular | The component (directly or transitively) consumes a SKU this BOM produces | Restructure so no SKU depends on itself, typically via a separate sub-assembly |
| Can't remove an output, or can't change its kind | It's the main output and other outputs exist | Choose **Main** on another output first |
| A line item's unit shows as invalid | The stored unit isn't among the component SKU's defined conversions | Add the conversion on the component SKU, or pick a valid unit |
| Deleting a BOM fails | A policy still references the BOM | Remove or re-scope the referencing policy first |
| A BOM is missing from the list | It is **Archived**, and the list hides archived BOMs by default | Add **Archived** in the **Status** filter |
| An Active BOM is never planned at a site | No enabled production rule covers it there | Enable or add a production rule naming the BOM at that site, or one for the whole SKU |
| An archived BOM is Active again but still not planned | Archiving disabled its production rules, and making it Active does not re-enable them | Enable the production rules you want for it |
| A new revision from the source is never planned | It arrives as a Draft with no production rules | Make it **Active** and add a production rule for it at each site it should run |
