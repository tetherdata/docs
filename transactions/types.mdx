# Order types

Every order in Tether is one of four kinds. Your organization can also name its own order types on top of them, such as "ITR" or "Sample PO".

## The four kinds

**Where:** Transactions → **New order** → **Kind** (or **Type**).

| Kind (in the editor) | Filter value | What it does |
|---|---|---|
| **Buy — purchase** | Purchase | Buys goods from a supplier into one of your locations. Has a supplier, PO number, unit prices and currency. |
| **Make — production** | Production | Turns components into a finished SKU using its BOM. Finished goods land at the destination. |
| **Move — transfer** | Transfer | Moves stock you already own from one location to another. No supplier, no purchase price. |
| **Sell — sales order** | Sale | Ships to a customer through a sales channel. See [Sales orders](/sales/orders). |

## What's the difference between a transfer and a purchase order?

**Where:** Transactions → **New order** → **Kind**: **Buy — purchase** vs **Move — transfer**.

A **purchase order** (Buy) brings new stock into your business from a supplier. It adds to what you own and carries a cost. A **transfer** (Move) only moves stock you already own between your own locations, for example from a 3PL to Amazon FBA. The source location's stock goes down and the destination's goes up when it's received. Use **Move — transfer** when the goods are already yours.

## How do I make an outsourced production order?

**Where:** Supply Chain → **Production** recommendations, and the order dialog's **Execution** field.

Whether a production run is **In-house** or **Outsourced** (made by a co-packer) comes from the production recommendation or from your connected system, not from a field you pick in **New order**. Planning shows it as **Execution: In-house / Outsourced** on the order. To change it, contact Tether. When an outsourced run is done, record it with [Report production](/transactions/report-production) and use **Reference** for the co-packer's run number.

## Can we have our own order types like ITR?

**Where:** Settings → **Transaction types**. You need permission to edit orders. Only shown if your organization uses order types. If you don't see it, ask Tether to turn it on.

Yes. A type is your name for an order, such as "ITR" for an inter-warehouse transfer. Underneath, each type is a purchase, production, transfer or sale, and that kind alone decides how it behaves. The type sets the name, the values a new order starts with, and which fields show.

1. Click **Add type**.
2. Fill in:
   - **Name** (for example "ITR")
   - **Is a**: Purchase, Production, Transfer or Sale. You can't change it later.
   - **Starts from** and **Goes to**: default source and destination
   - **Incoterms** (for example "DDP")
   - **Usually ships by**: **Container (FCL)**, **LCL (shared container)**, **Air** or **Truck / LTL**
   - **Prints as**: the document template its PDF uses. See [Document templates](/administration/document-templates).
   - **Ships in full** (transfers only)
   - **Hidden fields**: fields this type doesn't need, such as **Incoterms**, **Buyer** or **Unit price**
3. Save. The type appears in **Type** when you click **New order**, and as a **Type** filter on Transactions.

Use **Archive** to retire a type, and **Restore** to bring it back. Approval isn't set on this page. It's under Settings → Supply planning → **Plan approval**.
