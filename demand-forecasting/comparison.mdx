# Forecast Comparison

Forecast Comparison puts forecast models, submitted versions, baselines, actual sales and last year's sales side by side for the same SKUs, channels and periods. For some organizations it also scores past forecasts against what actually sold.

## Where is Forecast Comparison?

Where: **Demand** → **Comparison** in the sidebar (`/forecast-comparison`). The page title is **Forecast Comparison**.

- Most organizations see one view: the side-by-side comparison.
- Organizations with forecast run capture turned on see two tabs: **Compare forecasts** (the side-by-side comparison) and **Accuracy / vs Actuals**. If you'd like accuracy tracking, ask Tether to turn it on.

## How do I compare two forecast models side by side?

Where: **Demand** → **Comparison** → **Compare forecasts** → **Dataset**.

1. Click **Dataset** in the toolbar. The menu lists what you can add:
   - **Forecast Versions** (each submitted version, shown as "Version: …")
   - Models (each forecast model)
   - Baselines (each uploaded baseline)
   - **Actuals (Historical Sales)** and **Prior Year Sales**
2. Add the first model, then the second. The table then shows both models' values for the same rows and periods.
3. Narrow the rows with the filter chips (**Date Range**, channel, SKU group, SKU, hierarchy levels) and group them with **Grouping**.
4. Use the toolbar toggles to switch periods (**Daily**, **Weekly**, **Monthly**, **Custom Periods**), **Units** vs **Bundles**, and SKU **Names** vs **Codes**.

The page says "Select a dataset to begin" until you add one. To compare the forecast with what sold, add **Actuals (Historical Sales)**; for this year against last year, add **Prior Year Sales**.

## How accurate was last quarter's forecast?

Where: **Demand** → **Comparison** → **Accuracy / vs Actuals** tab → **Accuracy dashboard** (organizations with run capture turned on).

The accuracy dashboard scores retained forecast runs against actual sales. Filter it by channel, SKU group and model, and pick the **Horizon** (30, 60 or 90 days ahead).

The stat cards across the top:

| Card | What it means |
|------|---------------|
| **MAPE** | Mean absolute percentage error: the average size of the miss as a share of actual sales. Lower is better. |
| **Bias (signed)** | Net signed error: whether the forecast runs high or low overall. Zero means unbiased. |
| **Coverage** | Share of periods that could be scored, with how many were scored and how many were left out (censored). |
| **FVA vs naïve** | Forecast value added: how much better the model baseline is than a seasonal-naïve forecast. |

Below the cards, **Are we getting better?** charts MAPE and bias over time, and **Where to look — MAPE by model × horizon** shows which models miss most at which horizon.

<Note>
  Older docs listed **MAE** and **Hit Rate**. The app does not show those metrics.
</Note>

## Did our manual overrides make the forecast better or worse?

Where: **Demand** → **Comparison** → **Accuracy / vs Actuals** → **Accuracy dashboard** → the forecast value added (FVA) scorecard.

The scorecard scores each step of the forecast the same way and shows the change (**Δ vs prev**) each step made to **MAPE**:

1. **Naïve benchmark**
2. **① Model baseline**
3. **② + Manual overrides**
4. **③ Consensus**
5. **④ + Promo overlay**

If **② + Manual overrides** makes MAPE worse than **① Model baseline**, manual edits are making the forecast less accurate.

## Which of two forecast runs was closer to what sold?

Where: **Demand** → **Comparison** → **Accuracy / vs Actuals** → **Run comparison**.

1. Pick **Run A** and **Run B** from the retained runs (each shows when it was produced, its scope, model and inputs).
2. The chart plots both runs and **Actual (where known)**; set the **Grain** and the channel (**Channel: All** by default).
3. The movers table lists each **SKU · Channel** with **Run A**, **Run B**, **Actual**, the **Δ move**, and which was the **Closer run**.

## How do I switch to a better model after comparing?

Where: **Demand** → **Admin** → **Models** (organization default) or **Assignments** (per pairing).

Comparison doesn't change anything by itself. Pick the model your forecast uses on [Forecast Admin](/demand-forecasting/admin), or assign a model to particular SKU-channel pairings ([Model assignment](/demand-forecasting/model-assignment)). How each algorithm works: [Forecast Algorithms](/demand-forecasting/algorithms).
