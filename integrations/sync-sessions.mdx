# Sync history (executions)

Every time an integration syncs, Tether records a run — the app calls it an **execution** (you may also hear "sync session"). Each run shows what was fetched, what saved, and what failed and why.

## Where can I see why last night's sync failed?

Where: **Settings → Integrations → Data Ingestion → an integration → Executions**.

<Steps>
  <Step title="Open the integration">
    Go to **Settings → Integrations → Data Ingestion** and click the integration.
  </Step>
  <Step title="Find the run">
    Scroll to **Executions** — the latest 50 runs. Each has **Status**, **Domain Type**, **Started**, **Duration**, **Records** and **Stats** (✓ succeeded, ✗ failed, ⊘ skipped). Runs made in Dry Run carry a **Dry Run** badge.
  </Step>
  <Step title="Open it">
    Click the run. The **Sync Execution** page opens. If the run itself errored, an **Execution Error** card shows the message. Otherwise the **Sync Items** list shows each record and its error.
  </Step>
</Steps>

A run's status is completed, failed, running or cancelled. A completed run whose failed items are at least as many as its successful items is shown as **failed**.

<Note>
Only scheduled capabilities create runs here. Shopify **Fulfillment** arrives by webhook, so its events are in the integration's **Event Log**, not in Executions. See [Integration setup](/integrations/setup#fulfillment-warehouse-settings-and-event-log).
</Note>

## What's on a run (Sync Execution)

Where: **Settings → Integrations → Data Ingestion → an integration → Executions → a run**.

The header shows status, **Duration**, **Fetched** time, the data type, **Total**, and the success / failed / skipped counts.

**Sync Items** lists each record with **Status**, **Error**, **Fetched At**, **Domain Type**, **External ID** and **Records**. A layered icon marks an aggregate (batch) item; click its **N errors** to see which records in the batch failed.

Item statuses:

| Status | Meaning |
|--------|---------|
| **Processing** | Still being handled |
| **Success** | Saved in Tether |
| **Mapped** | Translated into Tether's records |
| **Partial** | Some of the item's records mapped and some didn't |
| **Failed** | Not saved — see the **Error** column |
| **Skipped** | Passed over on purpose — the **Error** column says why |

Filter with **All**, **Failed**, **Partial** and **Skipped**, search by external ID or error, filter by data type, or click **Export CSV** to download the items.

## Which SKUs didn't map in the last sync?

Where: **Settings → Integrations → Data Ingestion → an integration → Executions → a run**.

When records name SKUs or channels Tether doesn't recognize, a red banner at the top of **Sync Items** reads, for example, "3 Unmapped SKUs Found". It shows the most common ones with how many orders each affects.

- Click a SKU or channel chip to filter the items to it.
- Click **Show SKU Errors** or **Show Channel Errors** to open **All Unmapped SKUs** / **All Unmapped Channels**, with an **Affected Orders** count per code.

To fix them, see [Troubleshooting → Unmapped SKUs](/integrations/troubleshooting#unmapped-skus).

## How do I download the unmapped SKUs?

Where: **Sync Execution → Show SKU Errors → All Unmapped SKUs → Download CSV**.

The CSV has two columns, `SKU` and `Affected Orders`. **Copy All SKUs** copies the list instead. Channels work the same way from **Show Channel Errors**.

## Pack figures on product runs

Where: **Sync Execution** of a Products run → top of **Sync Items**.

When a products run reads pack sizes (for example units per pallet), it reports per pack unit: "Pallet figures: N added, N changed, N unchanged, N held for review". Figures **Held for review** are listed with the SKU, pack unit, units per pack and the reason Tether held them back instead of saving. Send the list to Tether support if a held figure is correct.

## How often does a sync run?

Where: **Settings → Integrations → Data Ingestion → an integration** → the schedule bar under the header.

Scheduled capabilities run on the integration's cron schedule; the bar shows the **Last** and **Next** sync times. Each run reads what's new or changed since the last one. Click **Sync Now** to run one immediately.

A full re-read from the beginning (**Reset Sync**) is a Tether staff action — ask Tether support.
