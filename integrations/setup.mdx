# Integration setup

Integrations connect Tether to the systems you already run — your store, ERP, 3PL, data warehouse — and sync orders, inventory, products and more on a schedule.

Where: **Settings → Integrations → Data Ingestion** (`/settings/integrations/ingestion`). There is no **Integrations** item in the main sidebar; old `/integrations` links open this page.

<Note>
You need the **Data Ingestion** settings permission (`settings:ingestion:access`) to see the page. If it isn't in your Settings, ask your administrator.
</Note>

For the list of services Tether connects to, what each syncs and its credential fields, see [Supported services](/integrations/supported-services).

## Where do I set up our Shopify (or NetSuite, ShipBob…) integration?

Where: **Settings → Integrations → Data Ingestion → New Integration**.

<Steps>
  <Step title="Open Data Ingestion">
    Go to **Settings → Integrations → Data Ingestion** and click **New Integration**. The **Create New Integration** dialog opens.
  </Step>
  <Step title="Name it and pick the service">
    Enter an **Integration Name** (for example "Shopify Production") and choose the **External Service**.
  </Step>
  <Step title="Choose capabilities">
    Under **Capabilities**, tick the data types to sync. Only the types the service supports are listed. Some pairs can't be on together — **Sales Orders** and **Fulfillment**, and (for most services) **Purchase Orders** and **Inbound Shipments**; a locked box explains why.
  </Step>
  <Step title="Set the schedule (scheduled capabilities only)">
    If any capability is pulled on a schedule, the **Schedule** section appears. Enter a **Cron Expression** (default `0 0 0 * * *`, daily at midnight) and a **Timezone** (default `UTC`). Webhook-only integrations, such as Shopify Fulfillment, need no schedule.
  </Step>
  <Step title="Enter credentials">
    Fill in the **Credentials** fields for that service. Required fields are marked with `*`. The fields for each service are listed on [Supported services](/integrations/supported-services).
  </Step>
  <Step title="Create">
    Click **Create Integration**. Tether opens the new integration's page.
  </Step>
</Steps>

<Tip>
Turn on **Dry Run** on the new integration's page before its first sync if you want to check what it brings in without saving anything.
</Tip>

## Does Tether integrate with ShipBob, SAP Business One, Cin7…?

Tether connects directly to 19 services, including ShipBob, SAP Business One, NetSuite, Shopify, Snowflake and TrackStar (which reaches many other 3PLs). It does not connect directly to Cin7, Amazon Seller Central, TikTok Shop, QuickBooks or Xero. See [Supported services](/integrations/supported-services).

## Data types (capabilities)

Each integration syncs one or more data types. How each arrives:

| Data type | What it brings in | How it arrives |
|-----------|-------------------|----------------|
| **Sales Orders** | Individual orders with their lines | Schedule |
| **Sales History** | Sales totals by period, channel and SKU | Schedule |
| **Pending Sales** | Pending or projected sales | Schedule |
| **Warehouse Inventory** | Stock levels by warehouse and SKU | Schedule |
| **Products** | Products, dimensions and SKUs | Schedule |
| **Bills of Materials** | BOMs with assembly and component SKUs | Schedule |
| **Purchase Orders** | Purchase orders placed with vendors, with lines | Schedule |
| **Transfer Orders** | Transfers between your locations, with lines | Schedule |
| **Inbound Shipments** | Inbound shipments and receipts a warehouse reports | Schedule |
| **Item Sources** | The vendors each item lists, with costs and lead times | Schedule |
| **Channels** | Sales channels for pricing and orders | Schedule |
| **Pricing** | Channel-specific SKU prices | Schedule |
| **Sales Forecast** | The active sales forecast | Schedule |
| **Forecast Versions** | Forecast data and versions | Schedule |
| **Baselines** | Baseline forecasts for demand models | Schedule |
| **History Series** | Dated figures (for example prices or counts) | Schedule; set up by Tether |
| **Fulfillment** | Order created, fulfilled, cancelled and refunded events | Webhook (Shopify) |
| **Shipment Fulfillment** | Shipments Tether sends back to the source as fulfillments | Outbound; turned on by Tether |
| **Store Stock** | How much of each SKU the store may sell | Outbound; turned on by Tether |

On the dashboard and capability cards, data types and delivery can show as raw codes, for example `sales_orders (cron_pull)` or `fulfillment (webhook_push_direct)`.

## The Data Ingestion dashboard

Where: **Settings → Integrations → Data Ingestion**.

Each row is one integration, with columns **Name**, **Service**, **Enabled** (a switch), **Capabilities** (each with a health dot), **Recent activity** (fulfillment events and errors in the last 24 hours), **Next Sync** and **Last Sync**. Click a row to open the integration.

## What do Healthy, Degraded and Failed mean?

Where: **Settings → Integrations → Data Ingestion** → the dot beside each capability (and on its card on the integration's page).

| Health | Scheduled capability | Webhook capability (Fulfillment) |
|--------|----------------------|----------------------------------|
| **Healthy** | The latest run succeeded and started in the last 24 hours | Subscriptions are registered and a webhook arrived in the last 24 hours |
| **Degraded** | The latest run failed or is more than 24 hours old, but not three bad runs in a row | No webhook arrived in the last 24 hours |
| **Failed** | The last three runs were all bad — failed, or refused at least as many records as they accepted | A webhook subscription is missing or not registered |

Outbound capabilities always show Healthy. For what to do, see [Troubleshooting](/integrations/troubleshooting#my-integration-says-degraded-or-failed).

## How do I run a sync right now?

Where: **Settings → Integrations → Data Ingestion → an integration → Sync Now**.

Click **Sync Now** at the top of the integration's page. It is disabled while the integration is turned off — switch **Enabled** on first. The run appears under **Executions** on the same page; see [Sync history](/integrations/sync-sessions).

You can also ask the agent: "Run the Shopify sync now."

## The integration page

Where: **Settings → Integrations → Data Ingestion → an integration**.

The header holds:

- **Edit** (pencil) — change the name, cron schedule and timezone.
- **Enabled** — turns all syncing for the integration on or off.
- **Dry Run** — every sync fetches and maps data but saves nothing. Runs show a **Dry Run** badge.
- **Sync Now** — runs a sync immediately.
- **Reset Sync** — Tether staff only. Deletes the integration's run history so the next sync reads everything from the beginning. Ask Tether support if you need a full re-sync.
- **Reset Fulfillment** — shown for integrations with Fulfillment. Deletes fulfillment events and backfill state so a fresh backfill can run; inventory isn't adjusted. Turn the Fulfillment capability off first.
- **Delete** — permanently deletes the integration with its capabilities, credentials and sync history.

Under the header, a bar shows the schedule and the **Last** and **Next** sync times. Below it, in order: a card per capability, **Credentials**, **Warehouse Configuration** and **Event Log** (Fulfillment only), and **Executions**.

## Capability cards

Where: **Settings → Integrations → Data Ingestion → an integration** → a capability card.

Each card has its own **Enabled** switch, a delivery badge, its health, and **Events (24h)**, **Errors (24h)** and **Unresolved errors**. Fulfillment cards add:

- **Inventory Backfill** — reads past events from a **Since** date. Turn the capability off first ("Disable this capability to run a backfill."), then click **Start Backfill**. Afterwards the button reads **Re-run Backfill**, or **Retry Backfill** if it failed.
- **Webhook subscriptions** — the topics Shopify sends, each registered (green), missing (amber) or failed (red), and the **Last signal** time. Click **Re-verify subscriptions** to check and repair them.
- **Inventory write-back** (Shopify) — when **Enabled**, publishes a Tether **Source warehouse**'s sellable stock as the store's Shopify availability. **Push now** republishes it immediately.

## How do I update an expired token or password?

Where: **Settings → Integrations → Data Ingestion → an integration → Credentials**.

<Steps>
  <Step title="Open the Credentials card">
    Click **Credentials** to expand it. Stored values are never shown, so every field starts empty.
  </Step>
  <Step title="Fill only what changed">
    Enter the new value — for example a new NetSuite **Token ID** and **Token Secret**. Empty fields are left unchanged.
  </Step>
  <Step title="Save">
    Click **Save**. You'll see **Credentials updated**. The next sync uses the new values; click **Sync Now** to check straight away.
  </Step>
</Steps>

You don't need to delete and recreate the integration.

## Fulfillment warehouse settings and event log

Where: **Settings → Integrations → Data Ingestion → a Fulfillment integration → Warehouse Configuration** and **Event Log**.

**Warehouse Configuration** sets, per warehouse, how fulfillment events are handled:

| Fulfillment Mode | What happens |
|------------------|--------------|
| **Internal** | Tether moves its own inventory when orders are created and fulfilled |
| **External WMS** | Tether holds no inventory for the order — the warehouse's own system owns it and reports stock its own way |
| **None** | Nothing is posted (the default when a warehouse isn't set) |

**Processing Delay (s)** waits before an event is processed. Click a row's edit button to change it.

The **Event Log** lists every fulfillment event (Order Created, Fulfilled, Cancelled, Refund, Updated, Draft Reservation) with its status: Success, Failed, Pending, Skipped, Replayed, Resolved or Superseded. Filter by date range, event type, status or warehouse, or search by order number. Click **Details** on a failed or skipped event to **Replay Event** or **Resolve** it — see [Troubleshooting](/integrations/troubleshooting#can-i-replay-a-failed-shopify-fulfillment-event).
