# Integration troubleshooting

Start every check on the integration's page: **Settings → Integrations → Data Ingestion → the integration**. Its capability cards show health, and **Executions** shows each run. See [Sync history](/integrations/sync-sessions) for reading a run.

## My integration says Degraded or Failed

Where: **Settings → Integrations → Data Ingestion** → the health dot on a capability.

**Scheduled capability (orders, inventory, products…)**

- **Degraded** — the latest run failed or hasn't run in 24 hours. Check that the integration and capability are **Enabled** and that **Next Sync** shows a time. Open the latest run under **Executions** for its error.
- **Failed** — the last three runs were all bad: they failed, or refused at least as many records as they accepted. Open the runs. An authentication error means [fix the credentials](#how-do-i-fix-an-authentication-failed-error); many unmapped SKUs means [map the SKUs](#unmapped-skus).

**Webhook capability (Shopify Fulfillment)**

- **Degraded** — no webhook arrived in the last 24 hours. That can be normal on a quiet store. Otherwise open **Webhook subscriptions** on the Fulfillment card and click **Re-verify subscriptions**.
- **Failed** — a subscription is missing or failed to register (amber or red topic). Click **Re-verify subscriptions**. If a topic stays red, check the store's **Access Token** and **Client Secret** in **Credentials**, then re-verify.

## How do I fix an authentication failed error?

Where: **Settings → Integrations → Data Ingestion → an integration → Credentials**.

The run fails at once with a credentials or authorization error and fetches nothing. Usually a token expired or was rotated, a password changed, or access was revoked in the other system.

<Steps>
  <Step title="Get a new credential">
    Create a new token or password in the other system (for example a new NetSuite access token, or a new Shopify Admin API token).
  </Step>
  <Step title="Update it in Tether">
    Expand **Credentials**, fill in only the changed fields (empty fields stay as they are) and click **Save**.
  </Step>
  <Step title="Check">
    Click **Sync Now** and open the new run under **Executions**.
  </Step>
</Steps>

You don't need to delete and recreate the integration. For each service's fields, see [Supported services](/integrations/supported-services).

## Unmapped SKUs

Where: **Settings → Integrations → Data Ingestion → an integration → Executions → a run** → "Unmapped SKUs Found".

The source sent product codes Tether doesn't recognize, so those lines didn't save. Common causes: a new product not yet in Tether, or a code that differs between the two systems.

<Steps>
  <Step title="Get the list">
    On the run, click **Show SKU Errors**, then **Download CSV** for every unmapped code and how many orders it affects.
  </Step>
  <Step title="Add the SKU, or link the code">
    If the product is new, create the SKU. If it exists under another code, open the SKU (**Products → SKUs → the SKU**), go to the **External IDs** tab, enter the system in **Type** (for example `shopify`) and the code in **Value**, and click **Add**. You need catalog write permission.
  </Step>
  <Step title="Re-run">
    Click **Sync Now** and check the new run. If orders from earlier runs are still missing their lines, ask Tether support to re-read them.
  </Step>
</Steps>

<Note>
If your organization uses the older SKU pages, a SKU's **External IDs** card is read-only — send the list to Tether support to map. Unmapped SKUs on Shopify **Fulfillment** events are mapped under **Settings → Inventory & Forecast → Fulfillment Mappings**.
</Note>

## Unmapped channels

Where: **Sync Execution → Show Channel Errors**.

The source named a sales channel Tether has no match for. Download the list with **Download CSV**. Either create the channel (see [Managing channels](/channels/managing)) or ask Tether support to map the source's channel to an existing one — channel assignment is part of the connection's [rule set](/integrations/data-mapping).

## Why didn't anything sync?

Where: **Settings → Integrations → Data Ingestion → an integration**.

| Check | Fix |
|-------|-----|
| **Enabled** is off on the integration or the capability | Turn it on |
| **Dry Run** is on | Runs fetch but save nothing — turn **Dry Run** off |
| **Next Sync** shows "—" | The schedule is missing; click **Edit** (pencil) and set the cron expression |
| The run shows **Skipped** items | Open an item — the **Error** column says why it was passed over |
| Fulfillment isn't moving inventory | The warehouse's **Fulfillment Mode** is **None** or **External WMS**; set **Internal** if Tether should move stock |

## Can I replay a failed Shopify fulfillment event?

Where: **Settings → Integrations → Data Ingestion → the Shopify Fulfillment integration → Event Log → Details**.

Yes. Filter **Status** to Failed (or click a red error badge), click **Details**, read the **Error** and its hint, fix the cause, then:

- **Replay Event** — processes the event again.
- **Resolve** — marks it handled without processing it, when you fixed it another way.

Both appear only on failed or skipped events. A SKU error hint points to **Settings → Inventory & Forecast → Fulfillment Mappings**; a WMS or connection error points to the warehouse settings above the log.

## A backfill failed

Where: **an integration → Fulfillment card → Inventory Backfill**.

"Backfill failed" shows the error (use **Copy error** to send it to support). Turn the capability off, pick a **Since** date and click **Retry Backfill**. To start completely fresh, use **Reset Fulfillment** (with the capability off) and run the backfill again — inventory isn't adjusted by the reset.

## Service-specific notes

| Service | Common problem | What to do |
|---------|----------------|------------|
| **Shopify** | Fulfillment webhooks stop | **Re-verify subscriptions**; check **Access Token** and **Client Secret** |
| **NetSuite** | Token-based authentication fails after a token is revoked or a role changes | Create a new access token and update **Token ID** / **Token Secret** |
| **SAP Business One** | Login to the Service Layer fails | Check **Service Layer URL**, **Company Database**, **Username** and **Password** |
| **ShipBob** | Inbound counts don't appear | Check the **Access Token**; counts come back after ShipBob receives the order |
| **Snowflake** | Run fails on a missing table or permission | The **Role** must read the tables, and **Warehouse** must be a running compute warehouse; check **Table Prefix** |
| **TrackStar** | No data from the 3PL | Check the **Access Token** and **Trackstar Connector**; the 3PL connection lives in TrackStar |
| **BigQuery / Redshift** | Query fails | Check the dataset/table (BigQuery) or **Orders Table** / **Line Items Table** (Redshift), and that the user can read them |

## Need a full re-sync?

**Reset Sync** deletes an integration's run history so the next sync reads everything from the beginning. Only Tether staff can run it — ask Tether support.

## When to contact support

Send Tether support:

- The integration name and service
- The run's time (from **Executions**) and its error
- For unmapped codes, the CSV from **Download CSV**
- For a fulfillment event, the order number and the error from **Details**
