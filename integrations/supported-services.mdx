# Supported services

Tether connects directly to the 19 services on this page. Each section lists what the service syncs into Tether (its **capabilities**, or data types) and the credential fields you fill in when you create the integration, using the labels you see on screen.

To connect one, go to **Settings → Integrations → Data Ingestion** and click **New Integration**. See [Integration setup](/integrations/setup) for the steps.

<Note>
A service's capabilities are what it *can* sync. Each integration turns on only the capabilities you choose, and Tether decides which ones fit your setup. Fields marked *optional* can be left blank.
</Note>

## Systems Tether does not connect to directly

Tether has **no direct connection** to these systems today:

- **Cin7**
- **Amazon Seller Central / Amazon SP-API** — Amazon data can reach Tether through [Snowflake (Fullwell)](#snowflake-fullwell) or a [TrackStar](#trackstar) connector such as Fulfillment by Amazon (`fba`).
- **TikTok Shop**
- **QuickBooks**
- **Xero**

If your data lives in one of these, it can still reach Tether through another connection — a data warehouse you already sync (Snowflake, BigQuery, Redshift), a TrackStar connector, or a file you upload. Ask Tether support which route fits.

## Shopify

Where: **Settings → Integrations → Data Ingestion → New Integration → Shopify**.

**Syncs:** Sales Orders, Products, Warehouse Inventory, and Fulfillment. Fulfillment is delivered by Shopify webhooks as orders are created, fulfilled, cancelled or refunded, so it needs no schedule; Sales Orders and Fulfillment can't both be on for one integration. A Shopify Fulfillment integration can also use **Inventory write-back** to publish a Tether warehouse's sellable stock as the store's Shopify availability.

| Field | Notes |
|-------|-------|
| **Shop Domain** | Your `mystore.myshopify.com` domain |
| **Access Token** | The Admin API access token (starts `shpat_`) |
| **API Version** | *Optional.* For example `2024-01` |
| **Shipping Confirmation Email** | *Optional.* `store_sends` (your store sends its own shipping email) or `shopify_sends` (Shopify emails the customer for each fulfillment) |
| **Client Secret** | Shown only when **Fulfillment** is selected. The app's client secret (starts `shpss_`) |

## NetSuite

Where: **Settings → Integrations → Data Ingestion → New Integration → NetSuite**.

**Syncs:** Products, Sales History, Warehouse Inventory, Purchase Orders, Transfer Orders.

| Field | Notes |
|-------|-------|
| **Account ID** | Your NetSuite account number |
| **Consumer Key** / **Consumer Secret** | From the integration record in NetSuite |
| **Token ID** / **Token Secret** | The access token for the integration user (token-based authentication) |
| **RESTlet Script ID** / **RESTlet Deploy ID** | *Optional.* Only if Tether reads through a RESTlet |
| **Query Config (JSON)** | *Optional.* Filters Tether applies when reading, set up with Tether |

When a NetSuite token expires or is rotated, update it in the integration's **Credentials** card — you don't need a new integration. See [Integration setup](/integrations/setup#how-do-i-update-an-expired-token-or-password).

## SAP Business One

Where: **Settings → Integrations → Data Ingestion → New Integration → SAP Business One**.

**Syncs:** Products, Sales Orders, Purchase Orders, Transfer Orders, Inbound Shipments. Tether reads SAP Business One through its Service Layer.

| Field | Notes |
|-------|-------|
| **Service Layer URL** | The Service Layer address |
| **Company Database** | The company database name |
| **Username** / **Password** | A Service Layer user |
| **Host Auth Key** | *Optional* |
| **Tether Reference Field** | *Optional.* A user-defined field, for example `U_TetherRef` |
| **First Read: Changed Since (YYYY-MM-DD)** | *Optional.* How far back the first sync reads |
| **Sales: First Read Changed Since (YYYY-MM-DD)** | *Optional* |
| **Sales: Invoices Dated From (YYYY-MM-DD)** | *Optional* |
| **Sales: Customers Read Elsewhere (BP codes, comma-separated)** | *Optional.* Business partner codes, for example `C1003, C1034` |

## Snowflake

Where: **Settings → Integrations → Data Ingestion → New Integration → Snowflake**.

**Syncs:** Products, Sales History, Warehouse Inventory, Purchase Orders, Transfer Orders, Bills of Materials, Item Sources, Baselines, and History Series (dated figures). Tether reads tables you prepare in your Snowflake account.

| Field | Notes |
|-------|-------|
| **Account Identifier** | For example `XXXXXXX-XXXXXXX` |
| **Username** / **Password** | A Snowflake user |
| **Database** | For example `MY_DATABASE` |
| **Schema** | For example `PUBLIC` |
| **Role** | A role that can read the tables |
| **Warehouse** | The Snowflake compute warehouse, for example `COMPUTE_WH` |
| **Table Prefix** | *Optional.* Prefix of the tables Tether reads, for example `TETHER__` |
| **Sales Start Date** | *Optional.* For example `2025-01-01` |
| **Units Per Pallet Column** / **Pallet Unit Column** | *Optional.* Columns holding pallet pack figures |

## TrackStar

Where: **Settings → Integrations → Data Ingestion → New Integration → TrackStar**.

**Syncs:** Warehouse Inventory, Sales Orders, Purchase Orders, Transfer Orders, Inbound Shipments. TrackStar is a hub that connects to many 3PLs, warehouse management systems and carts, so it is how Tether reads most 3PLs that aren't on this page.

| Field | Notes |
|-------|-------|
| **Access Token** | The TrackStar access token for your connection |
| **Trackstar Connector** | *Optional.* Which TrackStar connector the connection uses, for example `fba` |
| **API Mode** | *Optional.* `wms` (a warehouse) or `cart` (a store) |
| **Channel Name** | *Optional.* The sales channel to file orders under, for example `Faire` |
