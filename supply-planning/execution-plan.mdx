# Supply Plan

The Supply Plan (formerly the **Execution plan**) is where accepted orders are reviewed, approved and placed. Every purchase, production run and transfer someone accepted shows here until it is ordered. The solver plans around everything on it.

Where: Supply Chain → **Supply Plan** (`/planning/execution-plan`).

## Page layout

Where: Supply Chain → **Supply Plan**.

The page has three tabs: **Purchases**, **Production** and **Transfers**. Each tab's number counts the orders awaiting a decision. A warning triangle beside it counts orders that are approved but not yet ordered.

Each row shows its status:

| Status | Meaning |
|--------|---------|
| **Pending review** | Accepted, waiting for an approver |
| **Removal requested** | Someone asked to take it off the plan; an approver confirms |
| **Approved, not ordered** | Approved, but no order exists yet |
| **Ordered** | The order exists |

A row waiting longer than your organization's review threshold shows **Stale · waiting N days**.

Click a row to open the order: its lines, what it covers, what it is for, its rules, and any past rejections. If a tab has nothing to review, it says so, for example "No purchase orders to review".

## Approve the orders your team accepted

Where: Supply Chain → **Supply Plan** → **Purchases**, **Production** or **Transfers** → the row's **Approve**.

1. Open the tab and find the rows marked **Pending review**.
2. Click **Approve** on a row, or tick several rows and click **Approve** in the selection bar. A transfer is approved as a whole with **Approve transfer (N lines)**.
3. Confirm.

Where approving also creates the order, the button reads **Approve & create PO** (purchases) or **Approve & create order**, and the bulk confirm reads **Approve & create orders**.

What approval does is set per order type in Settings → **Supply planning** → **Plan approval**. It shows whether approval is required for each type and has an **Approval creates the order** switch. Leave the switch off if you enter orders in your ERP yourself, or every order would exist twice. Creating a production run from an approval is not available yet.

<Note>
  Approving needs approval rights. Without them you can see the plan but not the **Approve** buttons.
</Note>

## Place an approved order

Where: Supply Chain → **Supply Plan** → a tab → rows marked **Approved, not ordered** → **Place order**.

**Place order** creates the order in Tether. Open a row and use **Place order** in its details, or use **Place order** on an order-by group to place its rows together. Ordered rows are no longer editable here.

On Supply Chain → **Purchase** → **List** → **Approved**, the same approved buys are listed with **Place order**. See [Purchases](/supply-planning/purchases#list-views).

## Send approved POs to NetSuite (or your ERP)

Where: Supply Chain → **Supply Plan** → **Purchases** or **Transfers** → tick rows → **Send to NetSuite** (the button names your connected system).

1. Tick the orders to send.
2. Click **Send to &lt;your system&gt;** in the selection bar. Without a connected system, the button reads **Create & submit**.
3. Confirm **Send N orders to &lt;your system&gt;?**

A **Sending to &lt;your system&gt;** window lists each order as it goes, with **Submitted** and the reference number once it is written. If some fail, retry the failed ones from the same window.

Sending works for purchases and transfers. It needs an ERP connection for that order type; ask Tether to set one up if you don't see the button.

## Remove an order from the plan

Where: Supply Chain → **Supply Plan** → the row's **Reject**, **Remove** or **Request removal**.

- An order still **Pending review** offers **Reject**. It asks for a reason, the same reasons as [rejecting a recommendation](/supply-planning/recommendations#reject-a-recommendation-with-a-reason).
- An **Approved, not ordered** order offers **Remove**, or **Request removal** where removals need an approver. Until the approver clicks **Approve removal**, the order stays in the plan.
- **Just remove it** records no reason, so the plan may suggest it again.

To remove several, tick them and use **Remove** or **Request removal** in the selection bar.

## Orders approved but not yet placed

Where: Supply Chain → **Supply Plan** → the warning count on each tab; Supply Chain → **Purchase** → **List** → **Approved**.

The warning triangle beside each tab counts orders approved but never placed. They are on the plan but supply nothing until they are ordered. A past-due order that was never placed is flagged "Past due, not in the plan: send it or re-date it".

If placing an order stopped before your ERP returned it, a notice at the top reads "N orders are ordered but not linked to an order in your ERP". Click **Un-order** on each to take it back, then place it again.

## Create an order directly

Where: Supply Chain → **Supply Plan** → **New movement** → **Purchase**, **Transfer** or **Production**.

Use this for an order you know you need that Tether did not suggest. It joins the plan like an accepted recommendation.

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| No **Approve** buttons | You don't have approval rights, or the row is already approved | Ask someone who approves plans |
| **Send to …** missing | No ERP connection for that order type, or no rows ticked | Tick rows; ask Tether to connect the order type |
| Approved order still not in my ERP | **Approval creates the order** is off for that type | Use **Place order**, or turn the switch on in Settings → Supply planning → Plan approval |
| An order shows **Ordered** but isn't in my ERP | Placing it stopped before the ERP returned it | Use **Un-order** in the notice at the top, then place it again |
| Removed order came back as a recommendation | It was removed with **Just remove it**, which records no reason | Reject it with a reason instead |
