# Supply Planning Overview

Supply Planning is where Tether turns your demand forecast, inventory position, network, and policies into a concrete plan of purchases, production runs, and transfers. The plan is produced by Tether's planning service, which solves your whole network at once — every recommendation you see on the planning pages comes from the same solved plan.

<Info>
  The planning pages appear for organizations with supply planning turned on. In the sidebar, the **Supply Chain** group lists: Locations, Policies, **Connected Planning**, **Series Explorer** (if turned on), **Transfer**, **Production**, **Purchase**, **MRP** and **Supply Plan** (formerly Execution plan).

  The admin pages are one entry, Settings → **Supply planning**, with tabs: **Plan approval**, **Current plan**, **Solve history**, **Engine runs**, **Recommendation comparison**, **Never list** and **Data issues**. Each tab shows only to people allowed to open it.
</Info>

### Where did the Data issues page go?

Where: Settings → **Supply planning** → **Data issues**. It left the Supply Chain sidebar group. See [Data issues](/supply-planning/data-issues).

## The planning model

Every planning page reads from the same underlying data:

| Layer | What it is |
|-------|------------|
| **In progress** | Real, already-happening supply — open Purchase Orders, in-flight transfers, in-progress production runs |
| **Committed** | Orders you have accepted onto the [Supply Plan](/supply-planning/execution-plan) — the plan the solver must respect |
| **Recommended** | The solver's uncommitted suggestions from the latest solve |

The solver re-optimizes recommendations only when it runs. Committed edits you make between solves show on the grids immediately, but the solver's own suggestions stay as of the last solve until the next run.

## Plan freshness

Every planning page shows a freshness strip in its header:

```
Plan as of 2 hours ago · 3 edits since · next solve in 5 hours
```

- **Plan as of** — when the current plan was solved. Hover for the exact timestamp.
- **N edits since** — committed edits made after the solve. These are reflected on the grid now, but the solver's recommendations don't account for them until the next solve. The count is highlighted as a warning cue when non-zero.
- **next solve** — when the next scheduled solve will run, if one is configured.

The indicator only appears once a plan has been solved.

## Where do I run the planner?

Where: Supply Chain → **Connected Planning** → **Table settings** → **Run now**.

**Run now** is at the top of the **Table settings** panel on Connected Planning (it used to be a toolbar button). It reads **Running…** until the solve finishes, then every planning page reads the new plan. See [Connected Planning](/supply-planning/connected-planning#rerun-the-plan-after-changing-a-policy).

### Scheduled and automatic re-planning

Solves can also run without anyone clicking a button:

- **Scheduled solves** run on your organization's schedule, set in Connected Planning → **Table settings** → **Solver settings** → **Scheduled solves**. The next one shows in the freshness readout.
- **Automatic re-planning** is configured at **Settings → Automatic Re-planning**. When the toggle is on, every policy, network, or catalog change from upstream triggers a new solve. When off (the default), the planner only runs on manual or scheduled triggers.

<Warning>
  With automatic re-planning on, frequent upstream edits can queue many long-running solves. Turn it off if re-plans are getting in the way. Managing this setting requires the feature-flag management permission.
</Warning>

<Note>
  Running the supply solver is separate from generating demand forecasts. Forecast generation has its own admin surface — see [Forecast Admin](/demand-forecasting/admin).
</Note>

## Scenario (in Table settings)

Where: a planning page → **Table settings** → **Scenario**.

The scenario names which "world" the numbers come from. It used to be a strip across the top of each page; it is now a choice in each page's **Table settings**.

| Lens | Dataset | Question it answers |
|------|---------|---------------------|
| **Do nothing** | In progress | If I take no new action, where do I land? Only real, already-happening supply counts. |
| **Follow my plan** | Committed | If I do exactly what I've committed to, where do I land? In progress plus your accepted commitments. |
| **Tether's plan** | With recs | What does the solver want me to do? Committed plus the solver's uncommitted recommendations. This is the default on Connected Planning. |
| **No input limits** | Counterfactual | What could each production stage do if it were never constrained by its inputs — bounded only by its own capacity and demand? |
| **Engine run** | Engine run | Committed plus a recommendation engine's orders. Shown only where your organization takes that order type from an engine. |

The first three lenses are cumulative — each adds a layer on top of the previous one. Supply a lens excludes isn't hidden; it renders ghosted so you can see what each lens sets aside.

### The No input limits counterfactual

**No input limits** is different: it is a separate solved world served from its own paired relaxation solve, not a layer on top of Tether's plan. When it's active, a stamp shows like "Counterfactual solved 3 hours ago · committed supply current" — the counterfactual comes from its own solve, but committed supply and the position it projects are current.

The position is always offered, and disabled with a stated reason when it can't be selected:

- Not enabled for this organization.
- Needs a solved plan first — no plan run to compare against yet.
- The last plan run produced no no-input-limits comparison.
- The comparison could not be read (try again shortly).

<Info>
  The **Scenario** choice appears only on pages whose numbers re-project across scenarios (Connected Planning, Transfers, Purchases). Production has its own **Base position** and **Compare** — see [Production](/supply-planning/production). MRP, the Supply Plan and Data issues don't re-project.
</Info>

## Where recommendations come from

Recommendations come from one of two sources:

- **Tether's plan** — the solver. Each solve produces purchases, production runs and transfers for your whole network.
- **Engine runs** — for organizations that take some order types from a recommendation engine. Each engine run uploads its orders with the rules version that produced them. They are listed in Settings → **Supply planning** → **Engine runs**; see [Engine runs](/supply-planning/engine-runs).

### Why are my purchase recommendations coming from an engine run?

Where: Supply Chain → **Purchase** → **Table settings** → **Recommendations**; runs listed in Settings → **Supply planning** → **Engine runs**.

Your organization takes that order type from an engine. On Purchases, **Table settings** → **Recommendations** switches between **Tether's plan** and **Engine run**. A chip such as "Purchase recs not updated since Nov 12" means the engine hasn't produced new recs for the latest solve.

## Go back to yesterday's plan

Where: Settings → **Supply planning** → **Current plan**.

Every planning page, recommendation and report reads the current plan, which is the latest successful solve. If a solve produced a plan you don't trust, choose an earlier one here. The next successful solve takes over again automatically. Changing it needs permission to configure planning; past solves are listed under **Solve history**.

## Where to go from here

- [Connected Planning](/supply-planning/connected-planning): the whole network in one grid, **Run now** and **Solver settings**.
- [Transfers](/supply-planning/transfers), [Production](/supply-planning/production) and [Purchases](/supply-planning/purchases): the focus pages. Production's **Runs at risk** tab lists committed runs short on materials.
- [MRP](/supply-planning/mrp): material requirements for committed production.
- [Supply Plan](/supply-planning/execution-plan): approve, place and send what you've accepted.
- [Recommendations](/supply-planning/recommendations): accept, or reject with a reason.
- Settings → **Supply planning**: [Policies](/supply-planning/policies), [Engine runs](/supply-planning/engine-runs), [Data issues](/supply-planning/data-issues), and [why no recommendation](/supply-planning/why-no-recommendation).

## Best practices

<AccordionGroup>
  <Accordion title="Check the freshness strip before acting">
    Before accepting recommendations, glance at "Plan as of" and the edit count. A plan with many edits since the last solve means the solver hasn't yet re-optimized around your recent changes — run a solve first if the edits are significant.
  </Accordion>

  <Accordion title="Use the lenses as questions, not settings">
    Each lens answers a different question. Start on **Tether's plan** to see the full proposal, flip to **Follow my plan** to see where your commitments alone land you, and use **Do nothing** to see the urgency of acting at all.
  </Accordion>

  <Accordion title="Prefer scheduled solves over automatic re-planning">
    Automatic re-planning is powerful during heavy configuration work, but each upstream change queues a full solve. For day-to-day operation, scheduled solves plus the occasional **Run now** keep the plan fresh without surprise queue backlogs.
  </Accordion>

  <Accordion title="Use No input limits to find hidden constraints">
    If the counterfactual produces meaningfully more than Tether's plan for a SKU, some input (a raw material, an upstream stage) is the binding constraint. Cross-check with [MRP](/supply-planning/mrp) and [Data issues](/supply-planning/data-issues) to find it.
  </Accordion>
</AccordionGroup>

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| No planning pages in the sidebar | Supply planning isn't enabled for your organization | Contact your Tether administrator |
| Freshness strip missing | No plan has been solved yet | On Connected Planning, open **Table settings** → **Run now** |
| Recommendations look stale after edits | The solver only re-optimizes when it runs | Check "N edits since" in the freshness strip; run a solve to refresh recommendations |
| **No input limits** is disabled | The reason is stated below the control | Follow the stated reason: enable the feature, run a solve, or retry shortly |
| **Run now** stays on Running for a long time | Large networks take time to solve | Wait for completion; afterwards, check the clock-icon timing popover to see which phase dominated |
| I can't find **Run now** | It moved into **Table settings** on Connected Planning | Open **Table settings**; it's at the top |
| Today's plan looks wrong | A solve ran on bad data | Pick an earlier solve in Settings → Supply planning → **Current plan** |
